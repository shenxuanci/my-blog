# 评论管理通过博客后台服务端代理 Twikoo

博客后台复用现有 `admin` 会话，通过同源服务端接口调用 Twikoo 管理协议，而不嵌入 Twikoo 原生管理面板。这样浏览器不保存 Twikoo 管理令牌，也不接收邮箱、IP、UA 或评论 HTML；代价是仓库需要维护一层受限协议适配，并且由于选择让 Twikoo 管理密码与 `ADMIN_TOKEN` 相同，轮换后台口令时必须同步重置 Twikoo。

## Considered Options

- **直接使用 Twikoo 原生面板**：功能现成，但需要第二次登录，非腾讯云部署会把可直接管理评论的 MD5 令牌保存在浏览器 `localStorage`，并向页面暴露完整管理员字段。
- **把原生面板嵌入 `/admin/`**：减少自建界面，却要求放宽后台 CSP、引入跨域请求和第三方 UI 状态，安全边界与现有后台不一致。
- **为 Twikoo 使用独立密码**：隔离性更好，但单人后台多一份需要配置和轮换的秘密；本项目明确接受复用口令的耦合，换取较少的部署配置。

## Consequences

- Twikoo 必须在部署前手动初始化；运行时代码不得自动注册或重置管理密码。
- 关键词只在脱敏后的公开字段中匹配，不能借搜索结果探测邮箱或 IP。
- 评论内容只按纯文本进入后台 DOM；查看完整富文本应跳回公开页面。
- 已读状态只属于当前浏览器，不属于 Twikoo 的审核状态，也不跨设备同步。
- 代理固定连接已知 Twikoo 主机并禁止重定向；总超时覆盖响应头和正文，业务码与实际更新／删除数量都必须明确成功。
- 搜索、未读和删除检查的全量分页若出现总数漂移、缺页或重复记录，必须失败关闭，不能用可能遗漏回复的集合继续删除。
- Twikoo 没有带回复检查的事务删除；后台会在删除顶层评论前扫描并阻止已知有回复的评论，但仍保留极小并发竞态，因此有讨论内容时优先隐藏。
