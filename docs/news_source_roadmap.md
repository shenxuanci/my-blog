### 五门上线验收已退役（2026-08-10，ADR 0016）

「攒够 N 个有效日 → 解锁 `objectivity active` / 解锁补源」这层语义已经退役，理由与代价见 `docs/adr/0016-retire-five-gate-rollout-acceptance.md`。原因是结构性的：共享运行时指纹覆盖四个日常会改的管线文件，任何一次改动都会重置全部五门（含所谓「累计型」的 enrich 与信源指标），而管线平均每 1-3 天就有一次改动，14 日窗口因此不可达。台账 2026-08-10 行的实数是 `selection 1`、`trajectory 1`、`enrich 0`、`objectivity_shadow 1`、`source_metrics 1`。

现在还有效的是：

- **台账继续每日记录**，作为质量仪表盘。逐门计数、指纹重置、失败清零和缺口冻结的机制全部保留，只是计数不再通往任何开关，也不再输出最终确认结论。
- **客观性 shadow 已按累计样本封顶**：`shadow_mode:auto` 不再运行 shadow，需要采样时手动 `shadow_mode:force`。这一条与门退役必须同时生效——原先的门槛是唯一能关停付费 shadow 的开关。
- **enrich 文字质量改为人工随时抽查**，不再计连续日；台账继续自动记录 `removed_fields / enrichment_audited_events` 安全指标。
- **45 条夹具三轮门与配对成本门降为可手动触发的质量探针**，不再是阻塞项。`Objectivity Acceptance` workflow 保留，仍只读、仍限 `main`。

2026-08-05 的定时日报发布成功，但 objectivity shadow 在长驻进程内调用 `trafilatura` / `lxml` 时触发原生堆崩溃；提交 `a8941b0` / `1957a0b` 已把静态 HTML 解析隔离到可超时终止的一次性子进程，并将依赖锁、Python 完整版本与实现、runner OS/架构和 `RUNTIME_ENVIRONMENT_EPOCH` 纳入共享运行时指纹。该轮的生产树 `validate + shadow_mode:force` Run #31005512218 已成功，但那次的指纹此后已被两次生产改动取代，只作历史证据。

- 同日事件初次归并与发布前复核共享每次运行最多 20 次 LLM 调用；耗尽后仅合并共享同一原始条目的确定性重复，其余保留并告警。候选对数、桥接批次数、调用数、延后批次数和预算耗尽状态进入 `quality-health.json`，成本告警不阻断日报。

## enrich 文字质量：改为人工随时抽查（ADR 0016）

详情深化后的 enrich 同时停用新闻 `significance` 与 `why`，全文模式增加详情走向及更深的来龙／起因与现状；公开 interim 对摘要材料安全短写。按证据分为丰富材料、有限全文、摘要材料，最终审计后记录各档数量、`detail` 字数中位数及丰富材料达到 300 字且至少两段的比例。自动化回归只证明输入和合同正确，文字质量仍需人眼看。

原「5 个有效产出日」门已随 ADR 0016 退役——它的真实阻塞从来不是指纹重置，而是**人工回填这一步从未执行过**，所以计数长期停在 0。现改为：想抽查时就抽查，台账继续每天自动生成抽样清单和安全指标，不再累计天数、不再等达标。

- 台账每天从每个有内容的类目抽 1 条，清单写在当日台账行的 `enrich_sample`，随 `rollout-evidence-v2` 的 `enrich_review_cases` 保留有界证据。想抽查时直接读最近若干天的清单即可。
- 抽查看什么（沿用原判据，不再要求覆盖率）：丰富材料条目的最终 `detail` 是否达到 300 字且至少两段、正文是否落在 350–600 字区间；以及事实增量、无重复填充、无跨字段复述、归因正确和外行可读。起因片段还须逐条回溯且完整因果语义成立；短走向与详情走向的关键变量、可观察路标语义一致。
- 安全指标按 `removed_fields / enrichment_audited_events` 计算：分母是实际进入事实支撑/客观性审计的读者可见事件数；历史 interim 记录从同日日报 `stats.pick_count` 补全。只有最近 3 个有效新口径产出日齐全时才计算中位数基线，超过基线 1.2 倍时台账记 `needs_review` 告警；不足三日只记 `needs_review`，绝不回退到 `audited_events`。这条仍然自动跑。
- 发现文字质量问题时，只回退 enrich prompt 与类目输入格式，保留默认日报路由和操作菜单布局；最终生效事实以 `readme.md` 为准。不得靠减少审计、增加预算、切换供应商或追加调用补救。

## 中文视角对冲源评估（暂不推进）

实证（07-11~17 精选）：涉华条目单源率 56%，其中单源=西方外媒 ≈1.3 条/天，集中在大陆媒体不报的敏感议题（仅存单一西方叙事）。评估补一个中文国际视角源做涉华事件交叉：

- 候选路径：联合早报官网 RSS 已 404 判死（sources.yaml 尾注），重议只能走自建 RSSHub 的 zaobao 路由（如 `/zaobao/znews/china`），先浏览器验证路由可达再谈。
- 论证门槛：必须正面回应尾注"world 41% 过剩、任何 world 向新源默认拒"的定案——论据是"补涉华第二叙事"而非"加 world 产能"，可考虑低 credibility + mixed 类目接入以控制增量。
- 若路由不可达或增噪明显，明确记"不加"并销账。

原排序条件是「待客观性验收后判」，该验收已随 ADR 0016 退役，因此本项不再有自动到来的启动时机。它现在纯粹取决于是否真的想补涉华第二叙事——想推进时按下面的信源证据门自行判断即可，不必等任何计数。

信源证据门（保留判据，去掉日历要求）：在增加任何主管线信源前，先看现有源的 `source_health.json` 指标——抓取成功/零更新、候选量、入选量，以及手动 shadow 采样里的单源高风险率、独立证据链和集中度。只观测现有源，不回填历史、不同时加源；数据与人工审查都支持后才能重议。观测字段已在选材改革中补齐：`source_health.json` 逐源记录抓取条目、参与评分事件和参与最终精选事件；shadow summary 记录高风险单源率、独立链和来源集中度。样本够不够由人判断，不再要求连续 14 个有效日——那个窗口在当前开发节奏下不可达（见上文退役说明）。

## 动态线归因复核（随选材复核一并做）

原触发条件是「选材 7 日门最终确认时」，该门已随 ADR 0016 退役，本项改为随上文「选材改革后续复核」一并进行。

静态回退期不评价动态线。动态线实际启用后，每个产出日从 `score_history.json` 的 `eligible_scores` 计算两组过线候选数：`score >= 当日动态阈值` 与 `score >= 66`，记录两者差值、当日阈值及是否贴 `clamp` 下界。这个差值只衡量阈值对候选供给的影响，不等同于最终精选差异，也不能单独证明质量改善。

若动态阈值全程为 66 且候选差值全为 0，结论不得写「动态线有效」；若出现非零差异，只能先写「动态线改变了候选供给」，仍须结合人工质量复核判断是否有益。

已于 2026-07-26 补入 GitHub Issue #15 的口径原文（判据仍然适用，只是不再挂在某个门的达标时刻）：

> 最终确认时分开归因动态线：逐日记录 `threshold_source`、实际阈值、是否贴 `clamp` 下界，以及 `eligible_scores` 在实际阈值与固定 66 线下的过线候选数差。静态回退日不评价动态线；若动态期全程贴 66 且差值为 0，只能确认 `pick_max` 与 `min_per_category` 所在整包通过既有安全门，不得宣称动态线有效。非零差异仅证明候选供给发生变化，不直接证明质量改善。
